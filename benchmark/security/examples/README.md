# Malicious example archives

Generated by `benchmark/security/generate_examples.py`. Not in git — regenerate at will.
Every payload is intentionally small and harmless if accidentally extracted.

| archive | size | attack | expected secure-unzip behaviour |
| --- | ---: | --- | --- |
| `benign-control.zip` | 4341 B | ordinary small archive, no attack | extracts cleanly in both secure and --secure=no modes |
| `bomb-ratio-1000x.zip` | 1153 B | 1 MiB uncompressed from ~1 KiB compressed (ratio ~1000:1) | abort on expansion-ratio limit, or on --max-size below 1 MiB |
| `bomb-nested-3-levels.zip` | 277 B | zip nested 3 deep, innermost holds 512 KiB of zeros | must NOT recurse into nested archives; only the outer entry is written |
| `liar-declared-1kb-real-1mb.zip` | 1167 B | headers declare 1024 bytes uncompressed; stream really yields 1 MiB | must count ACTUAL bytes written, not the declared size, and abort |
| `slip-relative-traversal.zip` | 299 B | entry named ../../../tmp/secure-unzip-pwned.txt | abort: target escapes the destination directory |
| `slip-absolute-path.zip` | 180 B | entry named /tmp/secure-unzip-pwned-abs.txt | abort: absolute paths must be rejected (or stripped, never honoured) |
| `slip-symlink-escape.zip` | 272 B | symlink out -> /tmp, then out/pwned.txt written through it | abort: symlinks must not be followed outside the destination |
| `inodes-1000-files.zip` | 115022 B | 1000 tiny files in one archive | with --max-files=100: abort after 100 entries |
| `deep-directory-nesting.zip` | 2683 B | a file 256 directories deep | handle or reject gracefully; must not blow the path limit uncontrolled |
| `perms-0777-setuid.zip` | 282 B | files stored with 0777 and with the setuid bit set | with --max-mode=0644: written as 0644, setuid/setgid stripped |
| `names-control-chars.zip` | 603 B | entries with newline, backslash, dotdot-lookalike and non-UTF8-ish names | sanitise or reject; never let names break shell/log output |
| `duplicate-entries.zip` | 219 B | the same filename stored twice with different content | deterministic behaviour: last-wins or reject, never a partial merge |
