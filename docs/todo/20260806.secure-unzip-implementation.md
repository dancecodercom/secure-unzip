| D6  | Exit codes                                             | unzip-compatible **0 / 1 / 2 / 9**, plus **3 = security abort** (distinct, so scripts can tell a malicious archive from a missing file)                                                                                                  |
| D7  | Build & CI                                             | **Makefile + GitHub Actions.** `make build` cross-compiles into `bin/`; CI tests on push, attaches artifacts on tag                                                                                                                      |

## 5. Phase 2 — `security/` (pure decisions, no filesystem writes)

This package decides; it never writes. That is what makes it unit-testable without a disk.

### `errors.go`
A `ConstraintError` type carrying a constraint name (`zip-slip`, `max-size`, `max-ratio`,
`max-files`, `max-mode`, `symlink-escape`) and a message. Every error string must name its
constraint — the end-to-end tests assert on this, so treat the wording as a contract.

### `paths.go`
```
SafeJoin(root, entryName string) (string, error)
```
Order matters:
1. Reject absolute paths and any `..` element **before** joining.
2. Reject Windows drive letters and backslash separators in entry names (a `\` is a legal filename
   byte on Linux but a separator on Windows — normalise, don't trust).
3. `filepath.Join`, then `filepath.Clean`.
4. Assert `strings.HasPrefix(cleaned, root+separator)` — with `root` already
   `filepath.EvalSymlinks`-resolved by the caller.

```
CheckSymlinkTarget(root, linkPath, target string) error
```
Resolve `target` relative to `linkPath`'s directory, clean it, assert containment. Reject absolute
targets outright. **This is the subtlest code in the project** — give it the densest tests
(D5).

### `limits.go`
A `Budget` struct: `MaxSize`, `MaxFiles`, `MaxRatio`, with `AddFile()` and `AddBytes(n)` returning
a `ConstraintError` on breach. `AddBytes` is called from the streaming reader, so it must be cheap
and must **not** trust the zip header's declared size — the header is attacker-controlled and is
used only for an early-out check.

### `modes.go`
`MaskMode(entryMode, maxMode fs.FileMode) fs.FileMode` — bitwise AND, and always clear
setuid/setgid/sticky. `ReadOnlyMode(m)` → `0444`, or `0400` if the mask left no group/other read.

**Done when:** `go test ./security/...` passes, including table tests for
`../../etc/passwd`, `/etc/passwd`, `a/../../b`, `..\\..\\x`, deeply nested legal paths, unicode
names, and empty names.

## 6. Phase 3 — `extractor/`

Implements the ordered pipeline in `docs/agents/architecture/extraction-pipeline.md`. Steps 1–9
per entry, unchanged in order.

Staging (D4):
1. `os.MkdirTemp(destParent, ".secure-unzip-*")` — **sibling of the destination**, so the final
   move is a same-filesystem rename.
2. Extract everything into the temp dir.
3. On full success: move each top-level entry into the destination, then remove the temp dir.
4. On any error: `os.RemoveAll(tempDir)` via `defer`, then return the error.

Streaming write (`write.go`): a `countingReader` wrapping the entry reader that calls
`Budget.AddBytes` per read and returns the constraint error mid-stream, so a bomb stops expanding
at detection rather than after.

Directory entries: create with masked mode; **apply the read-only lock to directories last of
all**, after every file inside them is written, or the writes fail.

**Done when:** `go test ./extractor/...` passes against fixtures for each control.

## 7. Phase 4 — `main.go` and the CLI

Flags exactly as in `docs/agents/cli/command-line-interface.md`, with D1/D2/D8 defaults:

Flag resolution order (D9): build the profile from `--secure`, then overwrite with every flag
`flag.Visit` reports as explicitly set. `--secure=no` must warn on stderr, naming the disabled
precautions — including that zip-slip containment is off — unless `-q`.

| Flag | Default (`--secure=yes`) |
|------|---------|
| `--secure` | `yes` |
| `-d` | `.` |
| `-max-size` | `10737418240` (10 GiB) |
| `-max-files` | `10000` |
| `-max-ratio` | `100` |
| `-max-mode` | `0755` |
| `-read-only` | `false` |
| `-cpu-limit` | `0` — parsed, **no-op**, help text says "reserved, not yet implemented" |
| `--verbose` / `-v` | `false` |

Also `-q` (quiet) and `-o` (overwrite) for `unzip` familiarity, plus `-version`.

`--verbose` / `-v` (D10) prints resolved parameters before extraction and statistics after — files
generated, peak memory, CPU, MB/s — to **stderr**, even on abort. Full spec and the platform traps
in `docs/agents/cli/verbose-output.md`. Add `security/stats.go` (or `report.go`) holding a `Stats`
struct fed by counters the `Budget` already keeps, plus per-OS `rusage_unix.go` /
`rusage_windows.go` behind a small `peakRSS() (uint64, bool)` interface. **Test the `Maxrss` unit
conversion** — Linux reports KB, macOS bytes.

Exit codes (D6): `0` ok · `1` warnings · `2` generic/IO/bad-zip · `3` **security abort** ·
`9` archive not found. `main` maps a `*ConstraintError` to 3 and everything else to 2.

Accept `-max-mode` in octal (`0644`, `644`) — parse with `strconv.ParseUint(s, 8, 32)`.

**Done when:** `bin/secure-unzip -h` lists every flag with its default; a manual round-trip on a
benign zip matches `unzip` output.

## 8. Phase 5 — `testutils/` fixture generators

One generator per threat-model row, each writing a `.zip` to a caller-supplied temp dir.
**Fixtures are generated, never committed** — a zip bomb in git is its own problem.

| Generator | Payload |
|-----------|---------|
| `ZipSlip` | entry named `../../etc/passwd` |
| `ZipBomb` | ~10 MB of zeros compressing to a few KB, ratio >1000:1 |
| `InodeExhaustion` | 20,000 empty entries |
| `OverlyPermissive` | one entry with mode `0777` |
| `SymlinkEscape` | symlink entry pointing at `/etc/passwd` (D5) |
| `Benign` | small normal tree — the control case and the benchmark input |

`fixtures_test.go` asserts each generator actually produces the intended payload — a fixture that
silently degrades makes the whole suite pass vacuously.

## 9. Phase 6 — end-to-end security suite → `docs/benchmark/security_report.md`

`security_test.go` runs each fixture through **both** binaries and asserts the *difference*
(`CLAUDE.md` §3): secure-unzip catches/aborts/modifies while system `unzip` shows unsafe behaviour.
An assertion on secure-unzip alone does not satisfy the requirement.

**Containment is mandatory.** The system-`unzip` arm is *expected* to escape its destination, so
every case runs inside `t.TempDir()` with a destination nested deep enough (`root/a/b/c/dest`) that
`../../etc/passwd` lands inside `root`, never on the real `/etc`. Assert afterwards that the
escaped file appeared under `root` — that is the proof of the unsafe baseline.

Skip the `unzip` arm with `t.Skip` if `/usr/bin/unzip` is absent (CI on Windows).

The report is written by `go test -run TestSecurityReport` (or `make report`), containing a
per-fixture table: fixture · control · secure-unzip result · system unzip result · pass/fail.

## 10. Phase 7 — benchmark harness → `docs/benchmark/performance_report.md`

`scripts/benchmark.sh` (bash):
1. Preflight: require `hyperfine` and `unzip`; **detect `gtime`, else `/usr/bin/time`, else skip
   the RSS section with a visible note.** `gtime` is not installed here (§2) — the script must
   still produce a report.
2. Generate a benign fixture large enough to be measurable (~200 MB uncompressed).
3. `hyperfine --warmup 3 --export-markdown` comparing `secure-unzip` vs `unzip`.
4. Max RSS + CPU% via `gtime -v` when available.
5. Concatenate into the report with a header naming the machine, OS, and date.

Numbers are machine-specific: the report says so and must be regenerated, not trusted.

## 13. Risks and the remaining 10%

| Risk | Impact | Mitigation |
|------|--------|------------|
| **Symlink containment (D5)** is genuinely fiddly — TOCTOU via a symlinked *parent* directory can defeat a naive target check | Could ship a real escape | Re-resolve the containment root per entry; if the logic proves shaky in the run, fall back to skip-symlinks-and-warn and record it as a superseding decision |
| The zip-bomb fixture may not compress as hard as expected across zlib versions | Ratio test passes vacuously | `fixtures_test.go` asserts the achieved ratio exceeds the threshold |
| Windows permission semantics (A5) cannot be tested locally on darwin | Windows mode behaviour unverified | Guard with `runtime.GOOS` build tags; CI's windows runner is the real check |
| `Maxrss` unit differs (Linux KB, macOS bytes) and `getrusage` is absent on Windows (D10) | Peak-memory figure wrong by 1024× or a build failure | Per-OS files behind `peakRSS()`; `n/a` on Windows; unit conversion unit-tested |
| `gtime` missing (§2, verified) | No RSS numbers in the local report | Planned degradation, not a failure |
| Cross-filesystem staging: if `TMPDIR` differs from the destination FS, the final move stops being a rename | Slow or failing move on large archives | Temp dir is created as a *sibling of the destination*, not in `TMPDIR` |
| No git remote (A1) | Module path may be wrong | One-line `go.mod` change |

**Not in scope for this run:** `-cpu-limit` throttling (D8), encrypted/multi-volume archives,
non-zip formats, malware scanning.
